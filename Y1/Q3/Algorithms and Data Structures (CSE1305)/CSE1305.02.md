- to prove the big O runtime:
   - state we are looking if the function is O(g(n)), so g(n) = n means we are looking at linear complexity
   - the function we are analizing for time complexity is f(n)
   - the trick is that above some number ($n_0$) g(n) scaled by some number c will always be bigger.
      - the reason this works is because $6n^2$ will at some point ($n_0$) surpass $3n^2 + 20$
      - if however f(n) is a degree higher than g(n) then you cannot scale g with a c such that f(n) will never surpass it.
   - to formalize this: $\exist c, n_0 \space c > 0 \land n_0 > 0 \space \forall n (n \geq n_0 \to f(n) \leq c \cdot g(n))$
   - important note: a function that is O(n) is therefore necicarily also O(n^2)
   - terminology: tightest bound is always the 'lowest' big O expression that is applicable
- big-Omega ($\Omega(n^2)$ is basically the reverse of big-O: where big-O matches acurate and lower ($80n+10$ and $10n^2 + 5$ are $O(n^2)$) big-Omega matches acurate and higher:
   - $10n^2 + 5$ is $\Omega(n^2)$ 80n+10 is **not** $\Omega(n^2)$
   - $3n^3 + 6$ **is** however $\Omega(n^2)$
- big-theta ($\Theta(n^2)$): only when function is both big-O and big-Omega, people ofter use big-O where they mean big-theta because only big-theta is an exact match
