   - mac is sublayer of layer 2: data link
- sometimes (depending on medium) we can sense on the read wire if it matches with what i send: all is good, otherwise collision
   - in wireless you can subtract what you send from what you recieve to detcect collision
- detecting collision:
   - it takes $\tau$ time to reach from A to B
   - at $t = \tau$ we recieve the signal from A at B
   - so if B starts sending $\eta$ before recieving the signal ($\tau - \epsilon$)
   - then after at most $2\tau$ A will know about a collison because B started JAMMING when it detected it
   - can be corrected after $3\tau$
- ethernet is so reliable so we just don't do contention, but detect collision
- "the ambiguity of MAC" -> 'medium access control'
- ethernet was designed as a bus design, the hardware was used to decide if the transmission was for you
- original mac was "1-persistant CSMA/CD with binary exponential backoff"
   - wait until channel idle
   - when idle transmit and keep recieving
   - if detecting a collison backoff a random amount within range $[0, 2^i -1]$ where i is the amount of collions that have occured.
   - stop exponential after 10
   - give up after 16, then fail because "boo boo in the cable" is more likely
- ethernet frames
   - preamble: alternating set of 0 and 1 for the sake of syncing clocks
   - optional "start of frame byte" always 1
   - destination address: tells you which device it's for
   - source address: for replies, you know who to reply to, 48-bits, 24 of "organisation" and 24 of extension/board, all 1's is broadcast address
   - type / length: turns out type is quite irrelevant but length is quite usefull, if it's less than 0x700 it's probably a type, otherwise a length
   - data: there is no end frame marker, so we always check the CRC, if it's correct, we've found the end of the frame, only relavent if theres no length
   - padding, message should be atleast 72 bytes, this is because otherwise it's shorter than the contention period, ethernet cable shall be maximum 100m to make sure 72b is atleast 2 tau
   - crc
- the less number of stations the more efficient
- the larger the frames, the more efficient
- significant flat-off for stations above 4
- jumbo frame: 9000 byte frame; negotiate if reciever can handle jumbo frames
- we handle bitflips, since CRC is used for length you just don't do anthing, CRC includes source address so we can't even complain
- lost frames are a upper layer issue
- ethernet does not do ack's on negative acks
- wireless
   - range is effected by everything
   - multiple access with collision avoidance (MACA)
      - 'request-to-send', includes how long the message is, is echo'ed on the CTS
      - 'clear-to-send', only sent if nothing else is being recieved
      - there are sometimes still collisions
   - wifi uses stop-and wait because you cannot send data and recieve acks at the same time
   - 3/4 of network addapters do not implement RTS/CTS because it usually doesn't help due to the wierd field shapes
