- physical layer
- data link layer 
   - transmission delay is the time it takes to send all the bits
   - latency / propagation delay is the time it takes for the first bit to get from a to b
   - therefore the time it takes to recieve a message is always transmission delay + latency.
   - processing time may always be ignored for the sake of this course
   - utopian simplex protocol means data-link layer adds nothing, just turns the packet into a frame and sends it
   - ARQ is the simple protocol: receiver acks anything it receives, sender resends if no ack after timer expires
   - also called stop-and-wait: stop-and-wait means wait for ack to send next frame (number your frames & acks)
   - you can piggyback acks onto data
   - sliding window is any protocol that allowes for a given amount of un-ack'd frames
   - go-back-N throws out anything out of sequence, then waits for sender timeout.
   - selective repeat stores anything out of sequence, then sends a negative ack for the frame it's missing which is repeated, timers are still used
      - to do NAK's you can send an ACK a second time for the frame before the missing frame
   - you can decide to use cumulative ack's so when you say ack 4 you mean everything up to 4
   - byte stuffing is adding a flag byte to the beginning and end of frame to mark where frame starts and ends
      - then use an escape byte if that byte occurs without it being a flag, ploblem is is now you have to escape escapes and you can run into high levels of escaping
      - bit stuffing can be used to be more efficient, get a flag patern of bits. then each level of escaping is a different pattern of at least 1 bit more than previous level
- error control
   - error detection
      - parity bit, agree if all bits together should be odd or even, then add 1 bit to make it so (can detect odd numbers of errors)
      - parity word, split message into blocks of agreed upon length, then xor all together to get parity word, add that to end.
      - internet checksum, add all blocks together, then add the potential carry as well, then add the complement to the message as parity
      - CRC, make message divisible by g, agree on g, which has a binary length of k+1, append k bits to message
         - to send, add k zeros to msg, then apply long devision until you find the remainder, add 0's to the front until you have k bits, add that to the end of msg.
         - when applying long devision, don't subtract, XOR
         - to recieve, check if msg is divisable by g
   - error correction
      - parity blocks, BUH
      - hamming codes, remove powers of two (probably counting from 1), then somehow check for error
- mac sublayer
   - channel allocation:
      - aloha: send when data, wait random amount of time if collision
      - slotted aloha: divide into slots, then send within bounds of a slot
      - CSMA: 
         - p-persistant: if busy, wait for next timeslot, then send with p chance
         - non-persistant: if busy, wait random amount of time, retry
         - non-persistant grows like log with load factor
         - lower p is better for higher load but worse at low load
      - token ring: wait for the talking stick
      - bit-map protocol: during contention period everyone gets a minislot, then during transmit time transmit until empty in order of the bit-map
      - binary countdown: send the priority most-significant-bit first, if you detect something you did not send, back off, someone higher rank is talking
      - CSMA/CD: it takes 2t amount of time to detect a collision where t is the lancy to the other host that is colliding, therefore contention slots have tot be atleast 2t long, for the longest availble t
      - classic ethernet mac is 1-persistant CSMA/CD with binary exponential backoff
         - 8 bytes pre-amble are used with alternating 1's and 0's to sync clocks, in modern ethernet this is 7 bytes, then a byte which also alternates but ends in 11 instead of 10 to announce start of frame
         - because it takes t time to know for sure if you did not collide, no frame can be shorter than 72 bytes (when collision is detected a JAM signal is sent)
         - ethernet is connectionless, that's a TCP problem
      - CSMA/CA (MACA): use RTS and CLT to solve hidden or exposed terminal problem
         - CSMA/CA does not use normal p-persistant, it waits a random amount of slots, countdown is paused if another terminal is sending
   - switches operate on layer 2, they need to do some routing
      - backwards learning: if you recieve a frame from A on port 1, put port 1 -> A in the table, if you don't know, try all.
      - remove entries from table that have not been seen for more than roughly a minute
      - to avoid infinite loops, use the spanning tree protocol to build a spanning tree, only use that unless something breaks
- network layer (IPv4/IPv6) (routing from A to B)
   - DHCP
      - because no IP addr, broadcast
      - DHCP can provide gateway router addr
      - DHCP can provide NTP server addr
      - DHCP can provide DNS server addr
      - DHCPDISCOVER, get IP addr for this mac addr
      - DHCPOFFER, here is IP addr
      - DHCPREQUEST, i will take this ip
      - DHCPACK, okay
   - IP (internet protocol)
      - IHL (internal header length) can varie due to the amount of provided options in the options field
      - total length includes header and payload, max is 2^16 -1
      - header checksum which uses the internet checksum, as in add all word lengths, then add carry and then complement
   - routing 
      - routing table keeps which host has what cost and what line
      - distance vector routing: send the distance vectors you have to neighbors (only save the one with the lowest cost; send periodically and everytime something changes)
         - count to infinity problem: when some link dies 2 routers have each other as the route to the host
      - path vector routing, also store the path, that way you can detect count to infinity
      - link state routing, routers broadcast info about neighbors, then every router constructs image of the network. then apply dijkstra to destination
      - hierarchical routing: for a subgroup, only store one entry: to route to subgroup B (B1, B2, B3) i (A1) can route over A2 or A3)
   - fragmentation
      - non-transparent: router linked to the network with smaller packet size splits it up. host has no clue
      - transparent: on the other side of the small link the packet is re-constructed
      - MTU discovery: send back error telling host to send smaller packet size
      - IPv4 header: DF flag: dont fragment; MF flag: more fragments to follow; identification: ID of which packet this fragment belongs to; fragment offset: index into packet by how many 8-byte blocks of payload have perceeded it
      - IPv6 doesn't frgament, only MTU discovery is possible
   - not IP layer 3 protocols: 
      - ICMP, put in the payload and refered to in 'next protocol' header field
      - ARP (maps IP to MAC), more a layer 2 protocol
      - NAT (used for subnetting by forwarding certain ports to destination hosts)
   - congestion control
      - network provisioning (get human to upgrade network)
      - trafic-aware routing, choose routs based on traffic, split traffic over multip routes, include queue-ing delay for each router
      - admission control, (not widely used) only allow new traffic if it won't cause congestion, requires info about the traffic in advance (used in TOR)
      - traffic throttling, send signal there is too much traffic
         - precise (signal how much host's are allowed to send) vs inpercise (just signal this is too much)
         - explicit (send a message) vs implicit (like dropping packets)
         - end-to-end (tell only source to slow down) vs link-by-link (tell all links/routers seperatly)
         - XCP: explicit congestion protocol: explicit, precise, end-to-end (complex and experimental)
         - ECN: explicit gongestion notication: explicit, imprecise, end-to-end, tag a packet destination tells source to slow down
            - part of differentiated services: source sets 1 bit to comunicate support for it, router sets the other bit if congested
      - load shedding, implicit, imprecise, end-to-end: router drops packets when queue is too long, this loss is an implicit signal to slow down
         - RED (random early detection) the larger the queue, the higher the chance to drop packets
- transport layer (TCP/UDP) (providing ports, reliability, flow/congestion control)
   - only runs on source and destination
   - UDP (user datagram protocol)
      - segment structure: only provides ports and a checksum
      - error detection: checksum is internetchecksum (the additive one) computed over rest of header and payload. UDP does not automatically retransmit on checksum failure
   - TCP
      - segment structure 
         - header length to store options 
         - checksum, over payload and TCPheader (minus the checksum field), uses internet checksum
         - sequence numbers to detect missing packets and duplicate packets.
         - acknowledgement numbers
         - messages with the SYN, ACK or FIN flag do not have a body
      - error detection
         - 3 duplicate acks are seen as a NACK
         - sliding window, instead of k windows it's a given amount of bytes, this amount is set by congestion window
      - connection establishment and termination
         - both sender and reciever pick their own initial sequence numbers
         - when sending, the sequence number is your own intial sequence number + the number of previously sent bytes
         - the ack number is the inital sequence number of the guy you are ack'ing + the number of previously recieved bytes
         - SYN and FIN also add 1 to the sequence numbers
         - piggyback ACK by increasing ACK count, only set ACK flag if it's a loose ACK, see point above
         - initial sequence number is almost never 0
         - asymetric connection release can be forced by either party.
         - to agree on release (symetric disconnect) you go FIN, FIN, and the ACK the FIN
      - forbidden region
         - pick inital sequence number based on 32-bit time, then by sending bytes sequence numbers schould increase SLOWER than the time goes on.
         - timer resets to 0 after reaching 2^32 bits, if you cross the line you can no longer detect reconnects 
         - therefore, negotiote a new lower number that is from the timer. 
         - since you can take a max amount of hops, there is max amount of time the segment is in the network
         - to make sure the segment arives before the timer reaches the new number, renegotiate that max time before the timer reaches that
         - modern systems use randomized sequence numbers so an attacker cannot guess them
      - error correction 
      - flow control, used for small capacity receiver, uses window size field in header
         - the receiver sends the window size it can handle in the header field, the sender must then send segments of that size
         - silly-window syndrome: windows of 1 or 0 size: causes large overhead
      - congestion control
         - ECN can be negotiated, sender set ECE and CWR, reciever sets ECE during handshake
         - negotiation has to happen on TCP layer because IP is not connection oriented so it can't negotiate, the ECN is handled by IP.
         - when recieved, reciever sets ECE flag is set in next segment, sender sets CWR to ack that.
         - congestion window is then adjusted
            - TCP 'slow start': when we recieve ACK, double congestion window size (how many bytes can go unack'ed)
            - end 'slow start' on recieving a congested signal, or if reaching a threshold
            - after 'slow start' additive increase is common, linear groth by some arbitrairy amount
            - TCP TAHOE: 
               - congestion signal resets size to 1.
               - slow start threshold is set to HALF of the last WINDOW size
            - TCP RENO:
               - upon congestion signal, half threshold
               - set window size to threshold value, continue to additive increase
            - COMPOUND TCP:
               - like reno but measures queuing delay on routers and reduces sending rate if delays are high
               - windows
            - CUBIC TCP:
               - upon congestion signal, reduce window size to 70%
               - set threshold to previous window size, but cubic
               - linux, macOS and Win11
            - google BBR
               - reno + cubic, congestion signal is segment loss
               - and more scary stuff 
               - youtube and google trafic
      - TCP drawbacks
         - silly-window syndrome 
         - requires handshake
         - head-of-line blocking. out of order segments have to wait for retransmit
            - depence is assumed, so a video might have to wait for the comments to load
   - other layer 4 protocols
      - QUIC
         - UDP + flow/congestion control
         - connections and streams, in order is guaranteed per stream, streams are done with header field
         - can forgo handshake on reconnect
         - only 1 three way handshake
         - default congestion is CUBIC, other also available
         - same window size principal as TCP but on connection and stream level

- crypto
   - CIA: 
      - confidentiality: only authorized ppl can access data
      - integrity: if i say i sent it, i actually sent it
      - availability: information and services need to be available 
   - encryption:
      - symetric
         - stream ciphers: not really secure because you can decode some info about the message from XOR'ing 2 cipher texts
            - length of the key must be longer than that of the message
         - block ciphers: encrypt one block at a time
            - codebook: encryt each block, first one, then 2. highly parallelizable but identical inputs means identical output
            - cipherblock chaining: XOR first block with initial vector, then subsequent messages with previous block output, not parallel ofcourse
            - counter mode: concat initial vector with counter, then encrypt counter and XOR with message, this is parallelizable
         - block ciphers may use a long long chain of P-boxes and S-boxes
            - P-box: a P box swaps bits in a perdetermined order
            - S-box: convert bits to int, map each into to different int, then convert back to int's
      - asymetric 
         - RSA
            - find 2 large primes p and q
            - n = p \cdot q, $\theta(n) = (p-1)(q-1)
            - search for d & en such that $d \cdot e mod \theta(n) = 1$
            - public key is (e,n), private key is (d, p, q)
            - concept is p*q is easy, but facorizing is not
            - to encode, convert to sequence of number 1 to n, then encode as i^e mod n
            - to decript, x^d mod n
            - despite being uncrackable, is still deterministic, therefore long keys, also 'involve a nonce'
      - hybrid: use asymmetric-keys to exchange symettric keys
      - alternative to hybrid: diffi-hellman:
         - both parties pick a private part of a key, 2 public parts are agreed upon
         - then both parties mix their secret part with public parts, exchange the result
         - then add private part to recieved key, by the magic of diffi-hellman this will result in the same, symettric key
   - message authentication code
      - appended to a message to provide integrity, some authentication and repudiation
      - use a symmetric key to generate a tag for the message MAC(K, M)
      - reciever has same key and algorihm, also computse tag to check
   - digital sinature / pki
      - integrity, authentication, non-repudiation: everyone can prove who the sender is
      - use asymmetric key, sender signs with private key
      - others get  public verification key and can check message and signature
   - hashing
      - input becomes fixed length outcome
      - used by MAC to achieve integrity 
      - also used to speed up digital signatures: hash-then-sign
      - collision-rresistance: no 2 inputs have the same output
      - preimage resistance: unfeasible to find input from output
      - second preimages resistance: even if given 1 input and it's output. you cannot find the input of a given output
   - disclosure
      - non-disclosure: just ignore it
      - responsible disclosure: warn dev's give them a deadline
      - full disclosure: announce publicly immediatly
      - coordinated disclosure: involve the dev's with setting a deadline
- security
   - WEP (wireless encryption protocol)
      - easy to break, sends a clear text thing, you XOR that with the keystream, then add n(IV)
      - any man-in-the-middle will know c, c XOR keystream, and n(IV)
      - by litterally just XOR'ing the 'encoded' c with with you will get the keystream 
      - this allows mallory to encode their own 'challenge message' d, with the same keystream (the password)
   - WPA (WiFi protected Access)
      - Use message authentication code instead of CRC for data integrity
      - 128-bit keys 
      - new key is generated everyframe from 'master key' this means you can't reuse keystreams like with WEP
   - WPA 2
      - cipher-block chaining based MAC
      - AES encryptions which uses a counter mode
      - can do a mode with 1 password, and a mode with individual passwords
      - got hacked in 2017 with a patch
   - WPA 3
      - perma-fix 2017 KRACK attack.
      - more AES-bits (256)
      - SHA 2, for mack
   - threat detection 
      - signature-based: find known threats from patterns
      - anomaly-based: find deviations from normal
   - firewalls operate mostly on the network layer (IP) but may use transport layer (for ports) to disallow any disallowed trafic (based on white or blacklist)
      - to discard packets: if you discard on TCP you might have to discard multiple times due to retransmittions
      - alternative: send ICMP error
      - alternative: set the reset flag in TCP packet, thereby immediatly terminating the connection
      - stateful firewalls maintain a list of active connections, new ones are inspected throughly, established ones get little to none
      - deep packet inspection might want to inspect the contents of packet. kinda hard because of encryption, host might intentionally leak keys to help
   - IPsec: adds a header to the ip options, allows for tunneling and per-specifying the next IP header when emerging from the tunnel
      - used by for example VPN's
      - normal header+payload is encapsulated with new header, ESP header and MAC trailer
      - IPsec is not the best choice for commercial VPN's
      - Limitation: VPN knows the client and what they are accessing, anyone observing trafic going over VPN server can figure it out
   - onion routing:
      - key exchange: encrypt 3 times, relay 1 decryts once, relay 2 decyrpts once, and relay 3 does the last layer
      - response is encrypted onece before being sent, relays encrypt it
      - hidden services (darkweb): 
         - server chooses multip relays as introduction points
         - introduction points forward data between client and server
         - then normal union route between intro points
      - drawback is that message order is maintained
   - TLS (transport layer security):
      - usually on top of TCP
      - confidentiality and integrity
      - successor to SSl (secure socket layer)
      - HTTPS = HTTP + TLS
      - TLS 4-way handshake 
         - after TCP 3-way handshake
         - client: supported cihpresuits, TLS version, session ID, "nonce C"
         - server: chosen ciphersuite, certificates, public key, "nonce S"
         - client then verifies certificate, chooses secret for shared keys and computes keys
         - client: encrypts chosen secret with server public key. "finish message encrypted with shared keys"
         - server: "finish message encrypted with shared keys"
      - do a TLS handshake to agree on TLS version and cipher suits
      - setup a symmetric key for encryption and MAC's
   - MFA/2FA
      - something you know (password)
      - something you have (key, SMS code)
      - something you are
   - DNS spoofing:
      - faking being a DNS server to provide a false IP is DNS spoofing
      - tricking DNS server to provide wrong address is cach poisoning attack
   - PGP:
      - TLS is not good enough for messaging (like E-mail or text) because it has to go over other servers which might learn personal data
      - E-mail does not have native stuff for confidentiality or authentication
      - PGP uses public-key's to provide E-mail encryption, authentication, integrity and non-repudiation
      - uses, RSA, AES and hashing functions for these things
      - to send:
         - compute hash of message
         - sign hash with private key
         - choose secret key "k"
         - encrypt private key "k" with bob's public key
         - encrypt the (message concat signed hash) using the secret key "k"
         - send the encrypted private key "k" and the encrypted message
      - to recieve:
         - decypt the sent private key "k" using your own public-private key pair ("k" was encrypted with the public one)
         - then use "k" to decrypt the message with the signed hash concatted
         - compute the hash of the message
         - then use senders public verify key to check if the 'decryted' hash matches the computed hash
         - discard if not matched
      - Off-the-record messaging (OTR)
         - predeccessor of signals (and whatsapps) protocol's
         - only does 1-to-1, not group-chats
         - uses signatures for initial authentication
         - uses MAC's for integrity
         - publishes one-time MAC keys after use
         - to establish:
            - pick private diffi-hellman key, sign it, send it and send public key
            - reciever verifies and does the same. then you both compute the key
         - first message: send another private part and the symettrically encrypted message, then append the mac of the hash of the key computed over the other 2 parts
         - then send by encrypting with key mixed from last received key, and last sent key. 
         - every message, pick new next private part. receiver will respond by that mixed with previous thing
         - you can publish the MAC key once you know for sure bob has verified it and bob won't use it in the future
         - (so publish once you reciev a message starting with a key that does not consist of the key to be published)
