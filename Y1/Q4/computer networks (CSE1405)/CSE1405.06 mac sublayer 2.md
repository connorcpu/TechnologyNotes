## stuff
- hub just copies signals; operates on data-link layer
- switch operates on data-link layer, it uses mac-addresses to forward data
   - switch keeps table of what port is behind what physical port, mulitple addresses can be behind the same port, this way it just gets send to the correct switch
   - when you recieve a message with a from address, put that port with that address into the lookup table 
   - if the to address is not found, broadcast on all ports; upon recieve, update table
   - devices can move, this is dealt with by keeping track of when the last frame of a certain macaddress was seen, then periodically just remove the address from the table, order of magnitude is 1 min
   - there might be multiple routes for the same of redundency
   - this could create a loop by multiple swiches broadcasting the message; to solve this a spanning tree is created, and only that is used, if a fault occurs the spanning tree should be updated
   - the spanning tree protocol is used find this spanning tree
- the internet hangs together from ISP's joining their own networks
   - isp's are joined either over internet eXchange points (IXP) like the one in amsterdam
   - or via private peering, where 2 ISP's agree on how to join their networks
- IP addresses (IPv4 32-bit or IPv6 128-bit)
   - ip addresses are assigned by IANA which assignes ranges to regional internet registries who assign them to ISP's which assign them to people
   - ISP's have their own DHCP servers which assign IP's addresses
      - DHCPDISCOVER, ask's for IP addr
      - DHCPOFFER offers an IP address
      - DHCPREQUEST: ack's the new ip
      - DHCPACK: server ack's aswell
   - DHCP is found and comunicated with over broadcast; DHCP can give more info like default gateway, DNS etc
