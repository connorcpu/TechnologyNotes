- last week
   - go-back-N: discard frames with unexpected sequence numbers, retransmit all lost frames
      - sender knows something is lost because you set a timer for every frame you send
      - kinda wastefull
   - selective repeat: store unexpected frames, send negative acknowledgement
      - sender still sets timer, this allowes you to still resend even if the negative ack is lost or we are talking about the first or last frame
      - negative ack makes it go faster
   - utopian simplex protocol for frame loss
      - stop and wait: stop after send then wait
      - stop and wait with automated repeat request (no numbers): can resend but ack's cant get lost
      - stop and wait with numbering and ARQ: works but slow
      - sliding window with go back N: nows but wastefull
      - sliding window with selective repeat: seems to be the best
      - sliding window just means don't wait for ack to send next frame
