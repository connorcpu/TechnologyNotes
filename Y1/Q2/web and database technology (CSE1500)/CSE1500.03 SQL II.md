- where using ORDER BY, if you have multiple attributes (ORDER BY name, size DESC) DESC only gets applied to size, name is ASC (so alphabetical), first sort by first term, if that yields no conclusion (to names that start with the same letter), sort by the second term
- ORDER BY can be applied to a AS statement, even when the AS modifies the original value

- JOIN 
   - inner join (default): everything that has matching keys in both tables appears in output
      
   - outer join (for subtypes, outer is implied): 
      - left join: everything in first table must appear in output, if no matching entry is joined from joining table, NULL is provided
      - right join: everything in second table must appear in output, if no matching entry is joined from original table, NULL is provided
      - full join: left join + right join
   - natural join: just guess the value on which your joining 
   - cross join: cartieasion product, creates every option: {a,b,c}x{d,e,f}={(a,d),(a,b),(a,c),(b,d),(b,e),(b,f),(c,d),(c,e),(c,f)}
      - when using FROM x,y; cross join is implied
   - AS works on tables to make alias.attribute simpler, as can be implied by going "from person p1"
