# serial comms
- sync: have a shared clock signal (SPI & I2C)
- async: agree on baud rate (?) beforehand (UART)
   - start and stop bits
- UART: universal reciever/transmitter
   - frame structure: logic 0, 0-7 bits of info, optional parity bit, logic 1
   - lines are logic 1 when no info is being transmitted
   - full duplex
   - baud rate usually equals bit rate but officially equals symbol rate
   - LSB first
   - usually oversample by ~16x. try sampling near the center though
   - because you are sending 10 bits usaully you need the speeds to be within 10% for simplex systems because they never resample the clock speed
   - more complex controlers can resync their clocks every falling or rising edge
- SPI
   - SCLK, the shared clock
   - MOSI: from controller to peripheral (master out, slave in)
   - MISO: from peripheral to controller (master in, slave out)
   - ~CS (chip select, basically just a enable) BUT, must be low to be active
   - clock modes:
      - CPOL (clock polarity) determines what the state is if the clock is idling -> CPOL=0 means 0 will mean nothing ande pulses will be 1
      - CPHA (clock phase) determines if it's the rising or falling edge -> CPHA=0 rising edge, otherwise falling edge
   - with multiple devices you can share all lines between all devices just not the chip (slave) select
   - you can read analog valtages with an ADC
- I2C
   - SCL (clock)
   - SDA (data)
   - frame:
      - start: pull SDA low which SCL is high
      - send address, append logic 0 for write
      - ACK is sent by the reciever by pulling SDA low during the nith clock pulse
      - controller sends one 8-bit data byte
      - ACK again
      - stop: allow SDA to rise while SCL is high
   - the last bit of the address segment is 0 for write, 1 for read. so when you send a packet whith r/w = 1 the slave sends the data instead of the master
   - divices can pull a bus line low, but you need pull-up resistors to make the bus high

# timings
- dynamic discipline (using values that change at the wrong times)
   - t_ccq: clock to Q contamination delay, which is the time it takes between the clock striking and Q changing value (not neccisairly stable)
   - t_pcq: pclok to Q propagation delay: which is the time it takes between the clock striking and Q
   - t_setup: the time inputs should be stable before the rising edge of the clock
   - t_hold: the time inputs should be stable after the rising edge of the clock
   - t_setup + t_hold: the 'apature time', any signal that isn't held for this time can be ignored accidently
- system timing
   - Q is considered the input which is released from a register, so the register has it's own contamination and propegation time, being pcq and ccq, then theres the pd for the component, and the hold time for the saving register
   - T_c is the clock period (1/f)
   - T_c must be greater than the propegation delay, plus the setup delay, plus T_pd, which is the input to output propagation delay
   - as such, the t_pd must be smaller than T_t - (t_pcq + t_setup)
   - T_ccq + t_cd >= t_hold
- clock skew: clock signals do not arive at the same time
   - t_skew is the maximum difference in timing
   - contamination is measured from the first clock cycle
   - propegation is measured from the _last_ clock cycle
   - contamination is not realllly a thing when accounting for clock skew.
   - T_c >= t_pcq + t_pd + t_setup + t_skew
   - the signal is not allowed to arive until a hold time after the late clock's rising edge has occured.
   - t_cd > t_hold + t_skew - t_ccq
# FPGA architecture and design
- ROM
   - input gets decoded (address), then by connecting every adrress line to certain vertical output lines you can programm the output at a given address
   - several types
- PLD (programmable logic device) (generic term)
- PLA (programmable logic arrays)
   - allows programming of sum of products, by connecting the input wires in a grid into the AND gates you create the terms, then you just put all pairs onto 1 line. by having multiple lines you can have multiple outputs, even reusing pairs
- PAL (programmable array logic): programmable AND array feeding into a fixed OR array
   - all inputs are put on a central bus, both in normal and negated form
   - then you can make the terms by again just making connections so all signals are fed into an AND gate
   - then all and gates are fed into a fixed or gate.
   - the and gates and OR gate are fixed but you can program the AND gates. you can have 1 output per cluster
   - you can feed the output back into the bus to reuse it as input for other calculations
